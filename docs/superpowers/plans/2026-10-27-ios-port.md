# Implementação iOS

Escopo e decisões: [design](../specs/2026-10-27-ios-port-design.md). Portar a versão atual, sem alterações na implementação Android. A execução foi solicitada pelo usuário; trabalho dividido por arquivos independentes e revisão final.

## Contratos e responsáveis

- `ios/Packages/GameMapCore/Package.swift`, `Sources/GameMapCore/Models.swift`, `GeoMath.swift`, `NavigationEngine.swift` e testes de engine: worker core. Modelos públicos Codable/Equatable/Sendable, números Double e timestamps Int64 em ms; nomes dos tipos/campos iguais aos modelos Kotlin. Enums com casos Swift lowerCamelCase. `NavigationEngine.start(_:) throws`, `stop()`, `onFix(_:nowElapsedMs:nowWallMs:) -> EngineUpdate`, `onTick(nowElapsedMs:nowWallMs:) -> EngineUpdate`. Snapshot inclui fases/acessos/preferências Android e propriedades `navigationActive` e `guidanceAvailable`.
- Mesmo pacote, `GeoapifyProvider.swift`, `PlacesStore.swift` e testes: worker data. `NavigationProviding: Sendable` com `search(query:bias:) async throws -> [Destination]`, `route(origin:destination:) async throws -> NavRoute`. `GeoapifyProvider(apiKey: String, transport: any HTTPTransport = URLSessionTransport())`; `HTTPTransport.get(_ url: URL) async throws -> HTTPResponse`, resposta statusCode/body(Data)/headers([String:String]). Chave imutável por requisição, URLSession sem redirects, erros seguros, geração no runtime. Storage `PlacesStore(fileURL: URL, now: () -> Int64)` com `snapshot`, `savePlace(name:point:address:categoryId:iconId:id:) throws -> SavedPlace`, `deletePlace(id:)`, `setHome(id:)`, `setWork(id:)`, `rememberRecent(_:)`, `setResumeDestination(_:)`; SavedPlace/RecentDestination/LocalPlacesState preservam campos Android, `SavedPlace.asDestination()`. Storage síncrono com escrita atômica e erros explícitos, no main actor pelo chamador. Workers alinham modelos pelo mesmo contrato; avisar root antes de alterar nomes.
- Root: `ios/GameMap/App/`, `Platform/`, `Map/`, projeto Xcode, assets/preparadores/verificações e documentação. SwiftUI pode ser delegado após contratos estabilizarem.

## Etapas

- [x] Portar motor/modelos com regressões de continuidade, GPS, ETA, desvio e chegada no acesso viário.
- [x] Portar provedor real e armazenamento; Keychain/CoreLocation/runtime único com cancelamento e retomada segura.
- [x] Adaptar assets e renderer nativo; criar UI equivalente e catálogos reais com tema/câmera preservados.
- [x] Gerar projeto Xcode/esquema de testes/scripts e pacote transportável.
- [x] Validar o que o host permite, revisar fontes/integração e documentar limites concretos de compilação/assinatura.

80 XCTest de núcleo e 42 testes Node passaram. Resolver recursos e referências do projeto foi compilado/executado com Swift Foundation; fontes Apple passaram em parse e revisão de API. Build Xcode, testes Apple/pixels/iPhone e IPA assinado permanecem pendentes de Mac/conta/dispositivo; não estão implicitamente concluídos pelas etapas acima. Detalhes: `ios/docs/VALIDATION.md`.

## Verificação

Testes Swift reais no Mac: `swift test --package-path ios/Packages/GameMapCore` e `xcodebuild test` no esquema. Neste Windows, verificar estilos e URLs, hashes, contagens/catálogos, estrutura PBX e vínculo de todos os fontes/testes, permissões/privacidade, além de `npm test` para preservar Android/web. Se houver compilador Swift viável, executar testes portáveis; sem ele, registrar XCTest como escrito e não executado. Nenhuma aprovação estática equivale a build Xcode ou pixels no iPhone.
